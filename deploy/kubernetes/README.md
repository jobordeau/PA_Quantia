# Kubernetes — Quantia deployment

Kustomize-based manifests for deploying the Quantia web application to GKE.

## Layout

```
kubernetes/
├── base/                   # Shared base manifests
│   ├── namespace.yaml
│   ├── web-deployment.yaml
│   ├── web-service.yaml
│   ├── web-ingress.yaml
│   ├── web-configmap.yaml
│   ├── web-secret.yaml
│   ├── web-serviceaccount.yaml
│   ├── web-hpa.yaml
│   ├── web-pdb.yaml
│   └── kustomization.yaml
└── overlays/
    ├── dev/
    ├── recette/
    └── prod/               # also ships a ManagedCertificate
```

## Per-environment differences

| Setting               | dev   | recette | prod  |
|-----------------------|-------|---------|-------|
| Replicas              | 1     | 2       | 3     |
| HPA min / max         | 1 / 2 | 2 / 4   | 3 / 10|
| ASP.NET environment   | Development | Staging | Production |
| PDB minAvailable      | 1     | 1       | 2     |
| Container CPU req/lim | 100m / 500m | 100m / 500m | 250m / 1000m |
| Container mem req/lim | 256Mi / 512Mi | 256Mi / 512Mi | 512Mi / 1Gi |
| Hostname              | dev.quantia.example.com | recette.quantia.example.com | quantia.example.com |

## Apply

```bash
gcloud container clusters get-credentials quantia-prod-gke \
  --region europe-west1 --project YOUR_PROD_PROJECT

kubectl apply -k deploy/kubernetes/overlays/prod
```

Replace `prod` with `dev` or `recette` for those environments.

## Secrets

The `quantia-web-secrets` Secret in `base/` contains placeholder values. In a
real cluster, replace it with one of:

- A Secret created by CI from a CI/CD secret store (the workflow in
  `.github/workflows/deploy.yml` does this).
- An [External Secrets Operator](https://external-secrets.io/) `ExternalSecret`
  pulling the value from Secret Manager (the password generated by the
  `cloud_sql` Terraform module is already in Secret Manager).

## Workload Identity

The base ServiceAccount carries an annotation
`iam.gke.io/gcp-service-account: REPLACE_WITH_GSA_EMAIL`. After applying the
manifest, bind the corresponding GCP service account:

```bash
gcloud iam service-accounts add-iam-policy-binding \
  GSA_EMAIL \
  --role roles/iam.workloadIdentityUser \
  --member "serviceAccount:PROJECT_ID.svc.id.goog[quantia-prod/prod-quantia-web]"
```

This grants the pod's Kubernetes ServiceAccount the GCP identity needed to
read from BigQuery, Secret Manager, etc.

## Local validation

```bash
kustomize build deploy/kubernetes/overlays/dev | kubectl --dry-run=client apply -f -
```

This catches kustomize syntax errors and obviously invalid manifests before
they hit a cluster.
